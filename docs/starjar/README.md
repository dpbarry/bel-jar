application and battle test, targeted 31 Dec 2026; Abella is next; others follow. Where a
choice would make RocqJar easier but \*jar narrower, **the platform wins**.

## The three things to remember

1. **Needs 1–2 (Shape, Meaning) never touch the backend.** RocqJar gets navigation, outline,
   rename, incremental symbols and syntax-plus-scope diagnostics *before its provider exists*.
2. **The platform is a library of compensations for weak backends.** A capable backend turns
   them off, so RocqJar is BelJar with subsystems *switched off*, not added.
3. **The December date outranks the abstraction — but not the platform.** Forking a *file* is
   a logged debt. Narrowing the *interface* to fit Rocq is not: the provider interface, the
   capability declarations and the conformance suite are the deliverable and may not be
   compromised for one application.
